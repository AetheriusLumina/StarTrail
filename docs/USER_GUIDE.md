# 星迹 · StarTrail 用户手册

StarTrail 在 Windows 的默认浏览器中阅读 GitHub 项目，程序和数据在本机运行。适合先发现项目、读懂用途，再整理感兴趣的仓库。

## 安装和开始使用

1. 从项目 Releases 下载 StarTrail_Setup.exe，支持 Windows 10/11 x64。无需安装 Python，本地中英文翻译环境随安装包提供。
2. 没装过直接安装；已有版本优先使用原安装目录。不要先删 UserData。安装器识别旧安装并保留数据，升级前做完整备份；备份失败会停止安装。
3. 桌面/开始菜单的 StarTrail 图标打开默认浏览器。浏览器页面需要本地程序运行，关闭标签不等于退出服务；点击侧栏“退出”停止后台程序。浏览器是否允许自动关闭标签取决于浏览器规则。
4. GitHub 连接可提高公开接口额度；不连接也可使用公开读取路径。设置中的 Codex 连接用于 AI 功能，连接前核对账户及额度。
5. 安装包目前未签名，Windows 可能显示未知发布者。只从项目官方 Releases 下载，并核对随包 SHA256SUMS；不从聊天或陌生网盘获取更新。

## 首页：两个榜单

### Star 增长

1. 多来源发现候选，GitHub 官方接口核实最近完整 UTC 日新增 Star，再排序。累计 Star、网站热度与日增是不同数据。
2. 北京时间 08:00 才结束前一个 UTC 日，因此在此之前，界面统计日可能比本机日历昨天早一天。这是统计截止口径，不应改成未结束的半天数据。
3. 已见过的历史前五紧凑显示；五个新发现不被历史项目占名额。不足五个如实显示，接口失败或未完成时保留上次真实结果。

### 自选关键词

1. 添加关键词并设置最低 Star。AI 保留原词并补充相关表达；程序用这些表达直接检索 GitHub，并合并 Trending、Trendshift 的公开项目；仓库身份和数字由 GitHub 核实。
2. AI 判断是否相关，再按官方累计 Star 排序。历史已展示项目与当天其他模块排重；仅进入候选但未展示的仓库以后仍可入选。
3. 开启设置中的“自动 AI 发现”并连接 Codex 后，新关键词可自动补充相关表达；固定来源由程序直接读取，不再让 AI 重复联网搜索或审核候选。增长榜始终使用官方统计和程序排名，不调用 AI。有效扩词缓存复用，手动继续会推进公开检索断点；完整项目理解仍由用户单独触发。
4. 只有关键词扩词和手动项目理解使用 Codex 额度；增长榜、直接来源采集和程序排名不用 AI。项目详情解释为单独手动操作。本地翻译免费，不消耗 Codex 额度。
5. 每天重新采集覆盖范围，新项目和内容变化进入核实。网页和 API 都有有限范围与请求预算，软件不保证 GitHub 全站零遗漏；候选数是本轮实际读取数，不是全站总数。

## 更新数据和看进度

1. “立即更新”是数据刷新，不受定时更新时间限制。重复点击复用活动任务，不启动重复批量调用。
2. 检索进行中可点击“停止本次检索”，保留已有结果和断点；已开始的调用可能仍计入账号额度。状态显示采集、核实、缓存、待处理及暂停原因。受理或部分完成不是全量完成。限流、断网、AI 失败时保留结果和断点，恢复后再继续。
3. 界面已保存日期和 GitHub 统计日分别表示本机保存与官方增长口径；从旧历史页面打开详情仍显示旧快照，不应误当实时数据。
4. 设置中的定时更新控制每日数据刷新。“立即更新”不受设定时间限制。睡眠时程序无法联网且不会主动唤醒电脑；恢复后补检查当天未完成的更新。失败至少隔一小时再试，每天最多三次实际自动尝试，余下触发只检查是否到期。
5. 更新未完成时，顶部显示具体原因，十秒后自动关闭，也可随时关闭；设置保留最近尝试和原因。GitHub 授权失效需在设置重连，接口限流需等待额度恢复，网络错误需检查连接；重新登录不能替代软件缺陷修复。
6. 侧栏分别显示来源读取数、去重候选库、AI提交/完成、缓存及待处理。各榜单轮流推进，关键词合并完再统一分析；程序自身处理以60秒内为目标，外部网络和AI可能需要额外等待。某个模块先保存不代表全部完成。整组输入或模型上下文超限会说明原因，可调整关键词或模型后手动继续，不静默删除候选。

## 项目阅读、翻译与分类

1. 任意入口打开项目详情，都可以查看仓库、更新 README、关注与右上角“归类”。六块解释包含用途、问题、适合谁、功能、场景和使用门槛。
2. 手动 AI 解释后，“仓库原用途”第一行高亮说明它是软件、技能、库、算法、教程或其他类型；证据不足会说明不确定。旧缓存保留，想更新类型可主动重新解释。
3. 入选项目后台预译，译文保存在磁盘，内容不变不会因打开/关闭卡片重译。首次缺缓存会短暂准备；失败可先看原文并重试。代码、链接与仓库标识不翻译。
4. “归类”可以勾选多个已有文件夹，或创建新文件夹并一起保存；未关注仓库保存时自动关注，取消不更改数据。
5. 我的关注里“全部关注”不可拖动，未分类和自建文件夹可拖到其他文件夹。移动只移除当前源分类，其他分类保留；拖到未分类清空分类但保留关注。文件夹删除不删除关注仓库。

## 历史与设置

1. 历史日历按保存日期显示项目，点击日期回看；可以按名称/内容、日期和来源搜索。历史数字代表当时保存结果。
2. 设置可以管理关键词、阅读与字体偏好、动效、GitHub/Codex 连接、每日更新和自动 AI 发现。账号凭证只保存在本机，不应分享 UserData 或认证日志。
3. 默认保留森林透明主题，旧页面即时移除、新页面约 350ms 渐显；可按系统或偏好减少动效。

## 软件版本更新

1. 软件启动后和后台定期匿名检查官方 GitHub Releases，约六小时节流。只有更高版本同时提供匹配安装包和校验文件时才显示“软件更新”按钮。
2. 页面顶部提醒十秒后自动关闭，也可以手动关闭。关闭提醒不会取消侧栏更新入口，不会自动下载安装。
3. 点击“软件更新”查看版本和说明，确认后下载；程序核验大小和 SHA256，再启动安装器。正在更新数据或生成内容时先等任务完成，避免重叠写入。
4. 安装器在原位置备份数据、更新程序，再使用同一数据目录。自己下载最新版安装包也走相同保留和备份逻辑。源码运行模式需要手动安装，不让安装器覆盖开发目录。
5. 网络失败、摘要不符或备份失败保留原程序/数据并说明原因。下载失败可点“取消并删除自动安装包”，只清理本次自动下载；下载中先停止再删除，正在检查或已交给安装器时不能这样取消。不删除手动下载文件、其他包或备份。
6. 下载100%不代表安装完成。启动安装器后请在Windows任务栏找到其确认窗口，可能位于浏览器后方；连接中断只提示检查窗口，不冒充更新成功。不要为重试删除 UserData。

## 备份、恢复和卸载

1. 个人数据在安装目录 UserData。可在程序完全退出后复制整个目录作备份；目录含账号信息，应当私密保存。
2. 自动升级备份在 UserData/Backups/pre-update-*，只有含 BACKUP_COMPLETE.txt 的目录表示完整成功；不包含嵌套旧备份和安装包下载缓存。
3. 恢复时先关闭程序和计划任务，再另存现有数据，将完整备份复制回 UserData；不要在程序运行时替换 radar.db。跨电脑/Windows 用户的认证凭证可能需要重新登录。
4. 卸载可选择保留个人数据，重装到原位置可继续使用。选择删除数据不可恢复；保留的数据不应放进公开仓库。

## 遇到问题

1. 更新无结果：检查当前任务状态、网络/GitHub额度、Codex连接以及是否部分完成；不要反复点按钮消耗额度。
2. AI 解释失败：检查连接和返回格式，查看原仓库资料后再决定是否手动重试；软件不自动无限重试。
3. 翻译准备失败：先切原文，检查可用空间；使用缓存时无需重新加载模型。
4. 反馈 Issue 时提供版本、操作步骤、预期/实际表现和脱敏截图。不要附 Token、完整 UserData、个人路径或登录日志。

在设置的「软件版本」中可点「检查软件更新」主动检查最新安装包。这里显示当前版本和检查结果；失败会说明原因并允许重试。检查不更新项目数据、不消耗AI额度，也不自动下载安装。只有检测到新安装包，侧栏才显示软件更新按钮；顶部通知十秒后自动关闭，也可随时提前关闭。


来源覆盖状态：公开补充页记录 complete／partial／failed 与本次项目数。partial 表示页面有效但未覆盖后续目录，failed 表示该来源暂不可用；两者会在界面显示。它们不替代必须完整的官方查询与已知候选事实核算。前台增长的新仓库发现沿用 30 天窗口，旧候选仍更新和排名；全年代目录准备使用独立断点。同轮共享公开页面，下一轮重新请求。


### 第一次更新与长期留存

第一次广泛收集通常比再次更新慢。候选身份、名称、主题、来源、检索断点、扩词和榜单历史留存在本机；不是每次重新下载全部。原始日增证据保留最近30天，同一统计日的有效缓存复用六小时；新的一天仍更新官方数字。

前台更新没有固定分钟数截止；单次网络请求仍有超时。显示“等待GitHub额度恢复”时，已完成资料已保存，软件会按服务器恢复时间继续，仍可取消。睡眠时不能继续请求，恢复后按真实时间和日期检查；跨日旧任务不会冒充今日榜单。上方覆盖统计属于已保存榜单，本轮读取、核算、待处理与耗时另列。候选库中存在不等于已经推荐，也不代表GitHub全站覆盖。
